MOKOSH platform memory prerequisites — preparation 2026-11-01

Purpose: establish a narrow, repeatable native API baseline before designing
Windows and macOS equivalents of the reviewed Linux security components.
This package contains no application source, profiles, keys, personal files,
credentials, dependency installation, network client or host policy change.
It is not a product implementation or a complete security test suite.

Six native cases, eight assertions:
1. Lock one private anonymous page; check known synthetic bytes; make it
   read-only, inaccessible, accessible again; verify, zero own page, release.
2. Attempt a write to read-only memory in a dedicated child; require the READY
   precondition and an actual access violation, not an arbitrary failure.
3. Attempt a read from inaccessible memory under the same conditions.
4–5. Controls without those restrictions must actually read/write successfully;
   the unchanged denial oracle must reject those results as protection.
6. Deliberately waiting own child must start, reach deadline, be killed/reaped.
   This is ONE child, not a process-tree containment or job-object test.

Each probe uses only its own dedicated anonymous page. No Python heap pages
are changed. Child runtime <=30 seconds (waiting case 5), bounded output.
On POSIX RLIMIT_CORE=0 is set in each child. On Windows process error dialogs
are disabled. OS crash-report services may still observe deliberate faults;
only the fixed synthetic value is involved, never any real secret.
Normal runs write only a new output directory. Reuse is refused.

Current prototype families:
Linux/macOS: mmap, mlock, mprotect, munlock, unmap.
Windows: VirtualAlloc, VirtualLock, VirtualProtect, VirtualUnlock, VirtualFree.
The same process can re-enable its own memory access: intentional limitation.
This does not prevent arbitrary execution inside that process, external
privileged reads, compromised kernels, dumps, hibernation or all key copies.
No claim of absence from swap is derived from reading back a test value.

Native results bind OS, architecture, Python, page size, effective privilege,
probe SHA256, available GitHub run/commit and runner image metadata.
GitHub Windows runners normally use administrators; POSIX hosted runners may
have passwordless sudo. This diagnostic does not escalate and reports actual
effective privilege. Neither situation establishes an ordinary desktop or
hostile-process boundary for the application.

22 oracle tests include simulated result records for Windows/macOS; they are
parser/control tests only, never claimed as native results for those systems.
Green CI means only scoped API observations matched the specified assertions.
Product/backend/native integration/physical GUI/release acceptance stay false.
Windows/macOS implementations still require design and separate adversarial
checks for worker isolation, authenticated IPC, controller integrity, private
file access, safe publication, cleanup, cancellation and user interactions.

Manual workflow only. Fixed diagnostic path, no user-provided command/ref/URL.
Read-only repository token; checkout does not retain credentials. No secrets,
no permissions upgrade, no auto-merge/deploy/release, no scheduled background task.
Artifacts are an allowlist of SUMMARY.json, ORACLE_TESTS.log and native/RESULT.json.
Repository and Actions artifacts may be public; this payload is synthetic only.
No application files should be added to this diagnostic publication.
